# Vidstats implementation plan

## Approved design

`/vidstats [days]` and `vidstats [days]` create a video of the caller's existing listening report. Default 7 days, maximum 30, matching `/stats`. Preserve the full report and theme; highlight top-track rows in descending playcount order, with seven seconds of each song, no mixed audio. Five available tracks produce 35 seconds. Skip unavailable audio, keep its report row, explain missing audio. `/stats` remains a photo.

Audio resolution tries YouTube first, including candidate downloads. Only after that provider fails does SoundCloud run. Preserve resource bounds, cancellation, and cleanup. No deployment or new PR was requested in this turn.

## Implementation

- Terra agent `vidstats_impl`: reuse report drawing and layout; implement report frames, service and command routing using shared canvas admission. Update menu/help.
- Terra agent `audio_fallback`: own resolver only, implement sequential provider fallback and reconcile the recently added preview/cache path.
- Parent: inspect synced main, document feature, review integration and changes. No new tests or test execution unless requested by user.

## Review criteria

Rows match report geometry; ties preserve report order; audio never overlaps; seven seconds per available row; errors do not leak temporary media; commands do not hijack stats or other bot mentions; source timeout allows fallback; newer upstream canvas features remain intact.
